# ADR-0006：语音转写用「用户自备端点」，插件不自带模型

- 状态：已接受（v0.4 D1，2026-11-23）
- 相关：`docs/contracts.md` §3.15/§3.16、`lib/asr.mjs`、ADR-0005

## 背景

v0.1 起，语音作答一直只有半个：朗读题目用浏览器 `speechSynthesis`（ADR-0005），但「说话答题」不可用——`turn/answer` 只接受已经转好的文字，未配置时明确返回 `E_ASR_NOT_CONFIGURED`。

要做到「说一句话就能答题」，中间必须有一次语音转文字（ASR）。可选项有四：

1. 插件内置本地模型（whisper.cpp / faster-whisper）。
2. 用浏览器 `webkitSpeechRecognition`。
3. 上传音频到宿主由宿主转写。
4. 用户自备一个 OpenAI 兼容转写端点，插件只负责转发与归一。

## 决策

选 4，并在面板里给出配置入口（`asr/config`）。

## 理由

- **体积**：内置 whisper 权重 75 MB–1.5 GB，插件目前是零依赖、整个仓库不到 1 MB；为了一个可选功能把安装体积放大三个数量级不划算。
- **许可**：权重各有各的许可（部分仅限非商业），把许可风险塞进插件会把「零依赖」这条工程约束一起弄脏（ADR-0002）。
- **可测**：转发层是纯函数（拼 multipart、归一 response），可以用注入的 `fetch` 在毫秒级跑完；本地模型推理在 CI 里根本跑不起来。
- **可换**：用户手里可能已有 faster-whisper、one-api、DeepInfra、OpenAI 官方等任意一家；OpenAI 兼容形状是事实标准，转写质量由用户的端点决定，插件不背这个锅。
- **故障可见**：端点不通时错误是「端点不可用」，而不是「插件的模型坏了」——用户知道该改哪个配置。

## 被否决的备选

| 备选 | 否决原因 |
| --- | --- |
| 内置 whisper.cpp（wasm） | 首次加载 40 MB+，在面板里会卡住首屏；还要处理模型下载与缓存 |
| `webkitSpeechRecognition` | Chromium/Electron 里通常不可用（需要 Google 服务端），一开就 fallback，等于没做 |
| 上传到宿主转写 | 宿主没有公开的 ASR 服务；即便有，也不该把「谁的 Key」这个问题转嫁给宿主 |
| 不做语音（v0.1 现状） | 与负责人首条需求（m00001「文字对话和语音对话」）冲突 |

## 后果

- 想用语音必须先有一个 OpenAI 兼容端点；没有的话功能**明确降级**为文字，不假装录音成功。
- 端点地址、模型名、Key 存在 `$DSH_HOME/storages/dsh-mock-interview/asr.json`（0600），只写不读回；面板只能看到 `hasKey` 与掩码。
- 音频**从不落盘**：一次请求一个 Buffer，响应回来即丢弃；会话文件里只有转写文本。
- 上限：单段 8 MB / 120 s。超过就要求在本地缩短，不替用户切分。
- 若将来要内置模型，必须新写 ADR，并重新评估 ADR-0002 的零依赖结论。
