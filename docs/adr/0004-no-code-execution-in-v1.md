# ADR-0004 手撕代码只做静态评审，不执行代码

- 状态：已接受（2026-11-23）
- 影响：判题链路、安全面、报告可信度表述

## 背景

「手撕代码」要判断正确性，最直接的办法是真跑。但执行用户代码需要：进程隔离、超时、内存与文件系统限制、各语言工具链（JDK/Python 解释器），并且用户可能在代码里写删库、死循环、fork 炸弹。这套东西的工作量与安全责任都不属于 v1。

## 决策

v1 不执行任何用户代码，改为 LLM 静态评审：
1. 正确性推理：逐行说明算法是否达到题意；
2. 边界用例推演：评审方生成 5 条边界输入（空、单元素、重复、极值、非法），逐条推导期望输出与代码实际行为；
3. 复杂度与风格：时间/空间复杂度、命名、异常处理。

所有评审结果**必须**带「未真实执行」标注（UI 与报告都加），评分卡上单列一档「无法验证的风险」。

## 后果

- 好：零执行面、零语言工具链依赖，v1 可交付；静态推演本身也训练「说清边界」的能力。
- 代价：推演可能出错（LLM 算错用例或漏看分支），因此手撕题分数权重低于八股与项目深挖，且报告里把它标成「推定正确」而非「通过」。
- 触发复审：v2 若要真执行，需单独 ADR 定义沙箱（容器 + 只读根 + 网络关闭 + 资源上限），并以用户显式开启为前置。
