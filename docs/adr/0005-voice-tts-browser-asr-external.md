# ADR-0005：语音用浏览器 TTS + 自备 ASR，未配置时降级文字

- 状态：已接受
- 日期：2026-11-23
- 关联：章程 §7（明确不做多语言 / 不内置密钥）、`docs/contracts.md` §3.6.1

## 背景

「考核形式可以采用文字对话和语音对话」是用户提出的需求之一。插件跑在 DSH Web 端（Electron 渲染的 Chromium），需要的两种能力性质完全不同：

- **TTS（把题读出来）**：浏览器自带 `window.speechSynthesis`，中文语音由系统提供，零依赖、零密钥、零网络。
- **STT/ASR（把作答转成文字）**：Chromium 的 `webkitSpeechRecognition` 依赖 Google 在线服务，在 Electron 里通常不可用；要真正可用只能自带一个转写端点。

同时，插件不能内置任何密钥，也不能要求用户开箱即配。

## 决策

1. **TTS 走浏览器内置** `speechSynthesis`，语言 `zh-CN`，不做音频落盘。
2. **ASR 不内置**：留出自备 OpenAI 兼容转写端点的位置（密钥入 DSH credentials，日志脱敏）。
3. **未配置 ASR 时明确降级**：`turn/answer` 收到 `inputMode:'voice'` 但没有转写文本时返回 `E_ASR_NOT_CONFIGURED`，文案直接告诉用户「改用文字作答，或配置端点后重录」；客户端点「语音作答」不假装录音。
4. **失败不落盘**：语音相关的两种失败（未配置、转写为空）都在评分前拦截，会话文件里不会留下半成品。
5. **音频不存**：会话 JSON 只允许 `answer` 文本，`TC-VOI-003` 用正则断言文件里不出现 `audio` / `base64` / `blob`。

## 备选与否决理由

| 备选 | 否决理由 |
|---|---|
| 内置 Whisper 之类的本地模型 | 需要下载权重、占几百 MB、首次加载数十秒；插件定位是「练临场」，不该先花二十分钟装模型 |
| 用 `webkitSpeechRecognition` | Electron 下多数构建直接不可用，属于「看起来支持、实际点不动」的假功能 |
| 录制音频上传到宿主 | 需要新的上传通道与隐私说明，超出 v1 范围；录音也会变成敏感数据 |
| 不做语音 | 违背用户明确提出的需求 |

## 影响

- 语音作答在未配置 ASR 时**不可用**，这是显式的、有文案的降级，不是静默失败。
- 报告与评分路径与文字作答完全相同（`inputMode` 只做记录），所以降级不影响评分口径。
- 后续接入 ASR 时，只需把转写文本填入 `answer` 并保留 `inputMode:'voice'`，契约与评分层无需改动。
