# ADR-0001 面试页独立于主会话

- 状态：已接受（2026-11-23）
- 影响：UI 挂载方式、上下文隔离、数据存储

## 背景

模拟面试需要连续多轮、长提示词（人设 + rubric）、大量往返。若复用主 agent 会话：
1. 面试内容会挤占日常编码对话的上下文，用户回到工作时上下文已被面试消耗；
2. 主 agent 的 systemPrompt 是编码助手人格，与「面试官」人格冲突，只能靠临时指令覆盖，容易漏；
3. 面试页需要专门 UI（计时、录音、代码编辑、评分卡），聊天气泡装不下。

## 决策

面试会话自带一套页面与上下文：
- host 半用 `ctx.llm.stream` 直接调用宿主已配置模型，**不经过主 agent**；
- client 半注册 `sidebar.panellist` 图标（id `mock-interview`）与 `main` 页面（key `mock-interview`），形成独立整页；
- 会话数据落在插件自己的存储，不写入 DSH 会话历史。

## 后果

- 好：上下文互不污染；面试官人格只写一次；页面可容纳计时/录音/代码编辑器。
- 代价：需要在插件里重建「会话状态机」「消息渲染」，不能复用聊天气泡的流式、附件、滚动逻辑。
- 备选（未选）：用 `shell.overlay` 全屏浮层承载面试页 —— 保留为 A1 假设不成立时的退路。
- 备选（未选）：借 subagent 跑面试官 —— 人格可复用，但流式与中断恢复要跨会话编排，复杂度更高。
