# RC-001 模拟面试插件 · 需求卡

| 项 | 内容 |
|---|---|
| 编号 | RC-001 |
| 任务级别 | L3（新插件工程） |
| 章程 | `D:\project\04-docs\mock-interview-charter.md`（2026-11-23 已确认） |
| 背景 | 背题库练不出临场反应。真实面试的难点是追问、细节被戳穿、白板写不出边界条件，而现有工具只给「标准答案」，不给「你现在哪里不行、下一步练什么」。 |
| 目标 | 用简历 + 目标岗位生成一场针对性模拟面试，文字或语音作答，逐题评分并给出可执行的改进项，结束后留下可复盘报告。 |
| 交付形态 | DSH 插件：`sidebar.panellist` 入口 + `main` 页面，host/client 双半，RPC 单一端点。 |

## 用户故事

1. 作为求职者，我想把简历和目标岗位丢进去就开考，不必自己编题。
2. 作为求职者，我想被追问到答不上来，而不是听到一堆标准答案。
3. 作为求职者，我想知道刚才那句话到底错在哪、正确说法是什么。
4. 作为求职者，我想用说的方式回答，练口头表达。
5. 作为求职者，我想面试结束后有一份报告，隔几天还能回头看。

## 验收标准（Given / When / Then）

| ID | 场景 | Given | When | Then |
|---|---|---|---|---|
| AC-1 | 画像录入 | 一份 Java 后端简历与「Java 后端 / 中级」岗位 | 提交并请求解析 | 产出的结构化画像含技能栈、≥1 个项目、年限，且每个字段可在页面上修改；用户确认前不进入提问 |
| AC-2 | 出题对岗 | 画像已确认、模式为技术一面、时长 30 分钟 | 开始面试 | 题目数量落在 9 题预算内（±2），至少 3 题命中画像里的技能或项目，至少 1 题是手撕代码 |
| AC-3 | 动态追问 | 第一题回答只有一句结论、没有推理 | 判定该回答过于简略 | 面试官提出一次追问，追问必须指向该题的具体缺口；不换题、不放过 |
| AC-4 | 逐题评分 | 一道题已作答 | 请求评分 | 返回六维分数（正确性/深度/结构化/项目可信度/代码质量/沟通效率）、引用考生原话的证据 ≥1 条、缺失要点 ≥1 条、参考答案要点；非法 JSON 输出时重试一次，仍失败返回 `E_SCORE_INVALID` 且不写入会话 |
| AC-5 | 语音降级 | 未配置 ASR 端点 | 打开语音模式 | 界面明示「未配置语音转写，改用文字作答」，TTS 播报仍可用；不出现静默失败或假装在听 |
| AC-6 | 手撕代码评审 | 一道算法题及考生代码 | 提交评审 | 返回逐条边界用例推演、复杂度、命名/风格问题，并在结果里强制出现「未真实执行」标注 |
| AC-7 | 中断续考 | 面试进行到第 5 题，页面被关闭 | 重新打开该会话 | 会话恢复到第 5 题，已答题目与分数不重复计算 |
| AC-8 | 报告导出 | 面试已结束 | 导出报告 | 生成 Markdown：逐题分数与证据、总评雷达、Top3 短板、可执行改进清单；路径默认为当前工作目录 `./interview-reports/` |

## 非功能要求

- 单次 LLM 调用 P95 ≤ 15 s，硬超时 45 s（`E_LLM_TIMEOUT`）。
- 语音音频不落盘；密钥与简历内容不进日志。
- 会话 JSON ≤ 2 MB；页面首屏 ≤ 1.5 s。
- 核心 `lib/**` 覆盖率 ≥ 85%。

## 非目标（本期不做）

真实代码执行、视频面试、多用户/云同步、token 流式输出、英文面试、非技术岗题库、简历代写或岗位爬取。

## 假设

## 影响面

- 新增：`02-plugins/dsh-mock-interview/**`（独立包，含独立 git 仓库）。
- 触达宿主：`webServer`（新增一个 exact 路由）、`llm`（调用）、`credentials`（读取 ASR 密钥）、client `slots`/`locale`（注册图标与整页）。
- 不影响：主 agent 会话、systemPrompt、其它插件目录、宿主 checkout。
- 数据：新增 `$DSH_HOME/storages/dsh-mock-interview/`（会话与报告索引）。

## 风险登记（摘要）

见章程 §10；本项目内新增两条实现级风险：LLM 输出 JSON 不合法的重试策略、评分波动检测阈值（>1 档标注）。
